# Phase 5: Assignment Page Refactor

## Objective
Update `StudentsForAssignmentPage.java` to use the batch-fetching infrastructure introduced in previous phases. This will reduce the number of database queries from $O(N_{offerings} \times N_{users})$ to $O(1)$.

## Key Files & Context
- `src/org/webcat/grader/StudentsForAssignmentPage.java`: The target for refactoring.
- `src/org/webcat/grader/Submission.java`: Contains the batch-fetching API and `SubmissionGradingState`.
- `src/org/webcat/grader/UserSubmissionPair.java`: Contains the bridge methods to convert batch results to UI objects.

## Implementation Steps

### 1. Optimize Batch Fetch Prefetching
Update `Submission.submissionsForGrading(SubmissionGradingState state)` in `src/org/webcat/grader/Submission.java` to prefetch both the `result` and `user` relationships. (COMPLETED)

### 2. Refactor StudentsForAssignmentPage
Refactor `beforeAppendToResponse` in `src/org/webcat/grader/StudentsForAssignmentPage.java` to:
- Identify all displayed `AssignmentOffering`s.
- Gather all relevant users for these offerings (respecting `omitStaff` logic).
- Perform a single batch fetch using `Submission.submissionsForGrading(aos, usersByAO)`.
- Use `UserSubmissionPair.fromInfoMap` to populate `userGroups` and calculate `studentStats`.
- Populate `staffSubs` from the same batch results.
- Remove the redundant "prefetch everything" block. (COMPLETED)
