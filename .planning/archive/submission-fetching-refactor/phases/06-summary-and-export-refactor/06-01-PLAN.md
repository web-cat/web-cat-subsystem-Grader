# Phase 6: Summary and Export Refactor

## Objective
Update `StudentCourseSummaryPage.java` and `DownloadScoresDialog.java` to use the batch-fetching infrastructure. This will resolve the remaining $O(N)$ query patterns in the submission management UI.

## Key Files & Context
- `src/org/webcat/grader/StudentCourseSummaryPage.java`: Page showing a student's performance across all assignments in a course.
- `src/org/webcat/grader/DownloadScoresDialog.java`: Dialog for exporting scores to CSV (Blackboard/Moodle/Web-CAT formats).
- `src/org/webcat/grader/Submission.java`: Core batch-fetching API.

## Implementation Steps

### 1. Optimize Submission Prefetching
Update `Submission.submissionsForGrading(SubmissionGradingState state)` in `src/org/webcat/grader/Submission.java` to prefetch additional relationships (courseOffering, partner users) needed for exports. (COMPLETED)

### 2. Refactor StudentCourseSummaryPage
Refactor `beforeAppendToResponse` in `src/org/webcat/grader/StudentCourseSummaryPage.java` to:
- Collect all `AssignmentOffering`s for the course.
- Perform a single batch fetch for the `selectedStudent` across all these offerings.
- Use `UserSubmissionPair.fromInfoMap` to populate the `submissionsByAssignmentOffering` map. (COMPLETED)

### 3. Refactor DownloadScoresDialog
Refactor `collectSubmissionsToExport` in `src/org/webcat/grader/DownloadScoresDialog.java` to:
- Gather all relevant users for all `assignmentOfferings`.
- Perform a single batch fetch using `Submission.submissionsForGrading(assignmentOfferings, usersByAO)`.
- Replace the per-offering loop with logic that processes the batch results. (COMPLETED)
